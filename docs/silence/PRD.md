# Silence — 需求

按配置忽略指定消息：不改会话排序、不计未读；会话行与消息流里照常显示。

## 背景

会话列表用两个信号分配注意力：未读徽标，以及会话的位置（见 [chats-list](../chats-list/PRD.md)）。两个信号都由「来了新消息」驱动，于是固定节奏的噪声——构建机器人的每日产物通知、告警群里某个转发 sender、格式化日报——每来一条就把会话顶到最前并加一个红数字，而其中没有一条需要当场处理。

飞书自己的免打扰粒度到会话为止（`chats.muted`，只改画法：淡色计数加一个点），而噪声往往只占会话的一部分，群里其他人的发言仍要看。缺的是会话内按发件人、按内容的局部静音，且判定只在本机。

## 验收标准

1. 配置一条规则后，命中的消息到达时：会话不上浮、不出现未读计数、pane 头部与窗口标题的汇总不变。
2. 打开该会话，命中的消息在消息流里与其他消息无区别。
3. 同一会话里未命中的消息照常上浮、照常计数。
4. 删除规则并重启写者后，列表回到未配置时的状态。
5. 规则写错（id 拼错、内容不再出现）可被发现：`larkim silence` 报出每条规则的命中数与最近一次命中时间。

## 配置

```yaml
silence:
  - chat: oc_quiet
    sender: cli_c
  - chat: oc_quiet
    contains: "nightly build"
  - sender: cli_c
```

- 三个字段全部可选，写出来的字段取 AND；三个都空的规则在配置加载时报错。
- 多条规则取 OR。
- `chat` 与 `sender` 是 `chat_id` / `sender_id` 精确匹配。id 从 `larkim chats list` 和 `larkim contacts list --search` 取。
- `contains` 是大小写不敏感子串，匹配消息的人读渲染（`messages.content`）；渲染未到时退到原始 body。
- 只写 `chat` 即整会话本地静音，比飞书的免打扰更彻底——它连计数都不留。

## 行为

- 命中的消息不计入会话未读徽标、不计入头部与窗口标题的汇总、不把会话提进未读组、不改变会话在列表里的位置。
- 会话行的摘要与时间戳仍取该会话最新的一条消息，命中的也算：行的内容会变，位置不变。列表因此不隐瞒「那边有动静」，只是不把它排到需要处理的东西前面。
- 一个会话的消息全部命中时，会话沉到列表底部，与没有消息的会话同一区，行内仍显示最新那条。
- 打开会话时，命中的消息与其余未读一起记为本地已读，飞书客户端的红点照常清。
- 改完配置重启持 `daemon.lock` 的进程生效，随后一次全量重判落到所有历史消息上。

## 边界

- 判定只在本机：不写飞书的免打扰设置，不影响其他端。
- 不支持正则、不支持按 `msg_type` 静音、不支持时间段静音。
- 静音的消息在消息流里不带任何标记。
- 规则只从配置文件来，TUI 里没有编辑入口。
- 搜索与 `larkim messages` 不过滤静音消息，只多一个 `silenced` 字段：静音是列表的注意力口径，不是可见性开关。
